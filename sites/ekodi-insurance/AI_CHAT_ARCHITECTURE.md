# EKODI Insurance · AI-first Consultation

## 기본 원칙

상담의 기본 경로는 사람 연결이 아니라 AI 채팅이다.

1. 사용자는 EKODI Insurance AI와 먼저 대화한다.
2. AI는 기존 보험 이해, 보험료·보장 점검 순서, 보험금 청구 준비를 돕는다.
3. AI는 특정 보험상품의 가입을 확정적으로 권유하거나 보험금 지급을 보장하지 않는다.
4. 사용자가 실제 설계사 설명 또는 전화연락이 필요하다고 명시적으로 요청한 경우에만 Human Handoff를 연다.
5. 사용자가 연락처와 공유동의를 제출하면 상담요청이 생성된다.
6. 관리자 화면은 상담요청 목록에서 이름, 연락처, AI 상담요약, 요청시각, 처리상태를 먼저 보여준다.
7. 대화 전문은 사용자가 상담연결 시 공유에 동의한 범위에서만 상세화면에서 볼 수 있다.

## 상담 상태

- 신규
- 확인중
- 연락완료
- 종료

## 관리자에게 보이지 않아야 하는 것

Human Handoff 요청만으로 다음 데이터에 자동 접근할 수 없어야 한다.

- 사용자의 전체 보험계약 데이터
- 다른 청구사례
- 상세 건강정보
- 주민등록번호 또는 고유식별정보
- 다른 AI 대화

관리자는 해당 상담요청에 사용자가 공유한 `연락정보 + 상담요약 + 허용된 대화내용`만 읽을 수 있어야 한다.

## 실제 AI Provider 연결 전 조건

현재 공개 스테이징은 외부 AI Provider를 호출하지 않는다. 실제 모델 연결 시 다음을 먼저 충족한다.

- 보험/건강 관련 입력의 최소수집
- 모델 Provider로 전송되는 필드의 명시
- 불필요한 식별정보 Redaction
- 대화 저장 여부와 보유기간을 사용자에게 고지
- 학습 사용 금지 또는 이에 상응하는 계약/설정 검증
- 상담요청 시 별도 공유동의
- 프롬프트·모델·근거 문서 버전 기록
- 상품 추천 기능과 일반 안내 기능을 분리
- 관리자 열람 감사로그

## 운영 API 계약 예정

- `POST /ai/chat` : 최소화된 상담 컨텍스트로 AI 응답 생성
- `POST /consultations` : 사용자의 명시적 설계사 연락 요청 생성
- `GET /me/conversations` : 사용자 자신의 대화 조회
- `DELETE /me/conversations/:id` : 사용자 자신의 대화 삭제
- `GET /admin/consultations` : 허가된 관리자용 상담요청 목록
- `GET /admin/consultations/:id` : 해당 요청에 공유된 범위만 조회
- `PATCH /admin/consultations/:id/status` : 처리상태 변경

운영 전에는 중앙 Auth, 별도 Insurance 저장소, RLS/RBAC, 감사로그가 모두 검증되어야 한다.
