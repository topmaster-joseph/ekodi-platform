# EKODI Insurance Compliance Guardrails

기준일: 2026-08-15

이 문서는 개발 안전경계를 정리한 내부 설계 문서이며 법률의견을 대체하지 않습니다. 운영 전에는 실제 사업모델, 모집 주체, 제휴구조, 저장정보 범위를 기준으로 별도 법규 검토가 필요합니다.

## 1. 개인정보·민감정보

설계 원칙
- 건강·보험 관련 내용은 필요한 범위만 입력하게 한다.
- 고유식별정보는 MVP에서 받지 않는다.
- 서버 저장이 시작되는 시점에는 민감정보 처리에 대한 별도 동의, 목적, 보유기간, 철회·삭제 절차를 명확히 구현한다.
- 제3자 또는 상담자에게 전달되는 단계는 로컬 자기점검 단계와 분리한다.
- 동의하지 않아도 이용 가능한 기능과 동의해야 하는 기능을 UI에서 구분한다.

설계 참고
- 개인정보보호위원회는 2024년 개편 동의제도 안내에서 민감정보, 고유식별정보, 개인정보 제3자 제공은 계약 체결·이행 관계에서도 동의가 필요한 항목으로 설명했다.
- 공식 참고: https://www.pipc.go.kr/

## 2. 보험 비교·추천과 모집

현재 MVP는 다음을 하지 않는다.
- 특정 보험사·상품 순위화
- 특정 상품 가입 권유
- 보험료 견적 비교
- 청약서 작성 또는 계약 체결 중개
- 보험금 지급 가능성 판정

향후 비교·추천 기능을 검토할 때 필요한 최소 게이트
1. 실제 서비스가 보험업법상 어떤 모집·중개 역할인지 확인
2. 허용되는 상품·채널·사업자 자격 범위 확인
3. 추천 알고리즘의 공정성·설명가능성 검증
4. 수수료·제휴관계 및 추천 기준의 투명한 고지
5. 비교·추천 목적 외 정보이용 제한
6. 사용자에게 보험회사 공식 페이지로 넘어가는 시점과 책임주체 명확화

설계 참고
- 금융위원회의 보험 플랫폼 비교·추천 시범운영 방안은 플랫폼 역할, 알고리즘 공정성·투명성, 정보보호와 소비자보호 장치를 핵심 요소로 제시했다.
- 공식 참고: https://www.fsc.go.kr/

## 3. AI 점검

현재 AI 점검은 실제 생성형 AI 모델 호출이 아니라 브라우저 내 규칙 기반 점검이다.

금지
- '보험 적합도 92점' 같은 정밀해 보이는 임의 수치
- '이 보험은 부족합니다'처럼 약관 확인 없이 결론을 확정하는 표현
- '보험금 받을 수 있습니다' 같은 지급 가능성 단정

허용
- '우선 점검', '추가 확인', '기초 정리' 같은 확인 순서 제시
- 분석 기준 공개
- 실제 약관·보험사·적법한 상담을 통한 재확인 안내

## 4. 상담

스테이징
- 상담 메모는 브라우저 로컬 저장만 허용
- 실제 담당자 전송 금지

운영 전 필수
- 상담 목적과 수집항목 명시
- 최소 수집
- 전송 동의와 민감정보 동의 분리
- 수신 담당자 역할·권한 정의
- 열람·전송·삭제 감사로그
- 보유기간 만료 자동삭제

## 5. 실손·보험금 청구

현재는 준비서류의 일반적 예시만 안내한다.

운영 전 확인
- 공식 보험사/공공 청구 인프라 연동 가능 범위
- 의료·건강정보 전달 시 별도 동의와 위탁/제3자 제공 관계
- 업로드 파일 암호화·악성파일 검사·보유기간
- 청구 접수 성공/실패 상태를 사용자에게 명확히 표시

## 6. 운영 승격 금지 조건

다음 중 하나라도 미완료이면 `ins.ekodi.kr` 운영 라우팅을 활성화하지 않는다.
- 민감정보가 서버에 저장되지만 별도 동의가 없음
- 역할기반 접근제어가 없음
- 감사로그가 없음
- 상품 비교·추천이 있으나 자격·법규 검토가 없음
- AI가 지급 가능성이나 상품 적합성을 단정함
- 개인정보 삭제·철회 경로가 없음
