# 에코디몰 결제 운영 절차 (EKODI-MALL-PAY-RECON-001, 2026-10-23)

## 자동으로 처리되는 것
| 상황 | 처리 |
|---|---|
| 결제 승인 후 DB 기록 실패, 승인 응답 유실 | 10분 주기 대사(cron)가 토스 `GET /v1/payments/orders/{orderId}` 재조회로 `paid` 기록 |
| 결제창을 닫고 떠난 주문 | 만료(30분) + 유예 15분 후 `cancelled`, 잡아 둔 재고 복원 |
| 가상계좌 입금 대기 | 만료와 무관하게 대기 유지, 입금되면 웹훅·대사로 `paid` |
| 토스에서 취소·부분취소 | 웹훅·대사로 주문 `refunded`/`partially_refunded`, 전액취소 시 정산 `reversed` |
| 같은 상점(MID)의 다른 서비스 주문(큐티인 등) | 몰 웹훅은 무시하고 200 응답 |

웹훅 본문은 신뢰하지 않습니다. 항상 공통 결제 모듈(ekodipay-core, 프로필 `mall`)로 토스에 재조회한 상태·금액만 반영합니다.

## 사람이 하는 것
1. **환불(현재 수동):** 토스페이먼츠 상점관리자 → 결제내역 → 해당 주문번호(`mall_…`) → 취소. 반품 상품 재고는 판매자 화면에서 재고 수량을 다시 입력합니다(자동 재입고하지 않음).
2. **웹훅 등록(1회):** 토스페이먼츠 개발자센터 → 웹훅 → `https://ekodi.kr/ekodimall/api/public/payments/webhook` 등록, 이벤트 `PAYMENT_STATUS_CHANGED`·`DEPOSIT_CALLBACK`. 등록 전에도 10분 대사가 같은 일을 하므로 반영이 최대 10분 늦을 뿐 누락되지는 않습니다.
3. **로그 `mismatch` 확인:** 금액이 다르거나 취소된 주문에 승인이 도착한 경우 자동 반영하지 않습니다(`DONE_NEEDS_REVIEW`). 토스 상점관리자에서 확인 후 취소 처리하세요.

## 재고
- 상품 `stockQuantity`를 비우면 재고 관리 안 함(기존 상품 호환). 숫자를 넣으면 주문 생성 시 그만큼 예약 차감되고, 0이면 `out-of-stock`으로 결제가 막힙니다.
- 실물 직판 상품은 반드시 재고 수량을 입력하세요.
