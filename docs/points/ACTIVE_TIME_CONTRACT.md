# EKODI 활동시간 계측 모듈 — 운영 계약

이 모듈은 **사용자가 켠 사이트에서만** 동작합니다. 포인트 기능을 기본 비활성화 상태로 유지한 채 인증·활동 증빙·정책 승인 이후에 연결해야 합니다.

- 백엔드: `public.ekodi_points_active_heartbeat(site, session, foreground, recent_interaction)`. 서버 시각으로 경과 시간을 계산하고 KST 일일 한도와 canonical `people.id`를 검증합니다.
- 클라이언트: `points-active-client.js`의 `createEkodiActivityTracker({supabase,siteId,enabled})`를 명시적으로 호출해야 하며, 플래그 비활성화 시 어떤 API 호출도 하지 않습니다.
- 요청 간격: 15초. 처음 요청과 재활성화는 예열만 수행하고, 12초 미만 반복 요청·40초 초과 공백은 적립하지 않습니다. 사이트/회원별 단일 DB 세션으로 여러 탭에서 시간 중복 적립을 제한합니다.
- 단, 포그라운드·최근 사용자 조작 여부는 **브라우저가 보고하는 신호**이므로 자동화 도구로 위조 가능합니다. 서버가 계산한 시간이라고 해서 사람의 실제 집중이나 외부 공유 완료를 검증한 것으로 볼 수 없습니다. 부정 적립·보안 검토 전까지 저가치 포인트로만 설정하고 보상은 엄격한 일일 상한을 적용해야 합니다.
- `ekodi_point_sites.enabled` 및 `ekodi_point_rules(site_id,rule_id='active').enabled`는 기본 false로 유지합니다. 활성 규칙 최소 시간은 60~3600초입니다.
- 로그아웃하면 클라이언트 타이머와 세션 식별자를 제거합니다. 브라우저에서 적립금액·회원 ID·검증된 초·event_key는 보낼 수 없습니다.
- 사용자 화면 `/my/points/`에서의 체류 자체를 점수화해서는 안 됩니다. 실서비스에 연결할 때는 소속 사이트의 사용자 활동 화면에만 명시적으로 부착하세요.
- 별도 검증해야 할 항목: 서비스별 신원/사이트 연결, 로그인 인계, 동시 탭, 자동화 공격, 모바일 백그라운드 중단, 장기 미활동, KST 자정, 일일 한도, 실제 브라우저 E2E. 실제 사람의 시청·읽기·기도 참여를 증명한다고 홍보하면 안 됩니다.
