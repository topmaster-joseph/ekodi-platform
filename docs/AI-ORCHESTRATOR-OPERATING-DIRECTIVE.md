# EKODI AI Orchestrator Operating Directive

**Policy ID:** EKODI-AI-ORCHESTRATOR-DIRECTIVE-001  
**Version:** 1.0.0  
**Effective:** 2026-09-19

This directive applies the evolutionary autonomous AI operating rules beneath the EKODI Constitution and Sovereign Autonomous Operations policy.

## Core execution lifecycle

Current State → Root Cause Analysis → Design → Implementation → Test → Fix → Revalidation → Security/Permission/Performance Validation → Deployment → Production Verification → Prevention Automation.

A commit, PR, build, merge, or deployment is evidence of progress, not completion. Production-impacting work is complete only after the real production path and operational health are verified.

## Math and coding

Complex work is decomposed. Equations, assumptions, units, and boundary conditions are checked. Material results receive an independent cross-check where practical. Coding optimizes correctness, performance, security, scalability, and maintainability together and requires unit, integration, failure, and regression testing.

## Orchestration

Provider selection considers accuracy, cost, latency, security, and availability. Self-hosted/local/free/low-cost/high-performance-paid is a preference order, not a permanent mandate. Current verified EKODI policy and operating state always override stale preferences.

## Future compatibility

Specific provider, model, API, framework, domain, route, or deployment names are implementation details rather than permanent rules. Better technology may replace existing implementation only through current-state verification, policy conflict checking, sandbox/benchmark, canary, progressive rollout, and production verification.

AI may not expand its own authority, weaken security, bypass human sovereign gates, or claim unverifiable work as complete.
