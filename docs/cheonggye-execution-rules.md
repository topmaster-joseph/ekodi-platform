# 청계잇다 · 청계면상인회 강제 실행 규칙

이 문서는 `/cheonggye` 청계잇다 지역플랫폼과 `/cgma` 청계면상인회의 연결을 운영 코드와 동일한 기준으로 고정한다.

## 1. 역할과 소유권
- 청계잇다(`local:cheonggye`)는 청계 지역 공통플랫폼이다.
- 청계면상인회는 현재 위임된 주 운영단체이며 지역플랫폼 자체의 소유자로 간주하지 않는다.
- 상인회 회원명부, 회비, 임원, 회의·의결, 회계, 내부문서와 회원전용 자료는 `/cgma`가 소유한다.
- 지역플랫폼에는 승인된 공개정보만 투영하며 조직 내부 원본을 복제해 기준 데이터로 만들지 않는다.

## 2. 하위서비스 계약
등록되는 모든 지역 하위서비스는 다음 항목을 반드시 가진다.
- 고유 `id`와 `routeSegment`
- 사용자 공개 경로 `/cheonggye/{routeSegment}`
- 관리자 경로 `/cheonggye/admin/{routeSegment}`
- 주 운영단체와 운영단체 목록
- 공개 범위, 데이터 소유자, 소스정책
- 사용자 설명과 서비스 명칭

누락, 중복 경로, 존재하지 않는 운영단체, 잘못된 canonical 경로가 있으면 실행 계약 검증에 실패한다.

## 3. 현재 강제 대상
- 기관·단체·지역안내: `/cheonggye/directory`
- 상점·상권: `/cheonggye/commerce`
- 청계패스·지역상품권: `/cheonggye/pass`
- 지역행사·프로그램: `/cheonggye/events`
- 국민의숲·산림프로젝트: `/cheonggye/forest`
- 구인구직: `/cheonggye/jobs`
- 나눔마켓: `/cheonggye/sharing`
- 지역방송·라이브: `/cheonggye/broadcast`
- 주민참여·제안: `/cheonggye/proposals`

각 서비스는 동일한 관리자 하위경로를 가져야 하며, 특화 화면이 없는 서비스도 최소 운영면을 제공한다.

## 4. 접근·운영권
- Google 로그인 상태와 지역 범위 권한을 별도로 확인한다.
- CGMA 관리자라는 이유만으로 지역플랫폼의 권한관리 권한을 자동 부여하지 않는다.
- 공동운영·운영권 이양은 서비스별로 가능하며 변경 이력을 보존한다.
- 운영주체가 바뀌어도 지역 데이터는 이동·복제하지 않는다.

## 5. 금융 경계
청계패스의 쿠폰·할인·포인트 기능과 현금성 선불·상품권·정산 책임을 분리한다. 발행자, 결제사업자, 정산계좌와 규제 책임은 별도 승인 계약 없이 운영권과 함께 이전되지 않는다.

## 6. Fail-closed 라우팅
등록되지 않은 `/cheonggye/*` 하위서비스 경로는 청계잇다 메인으로 조용히 되돌리지 않고 404로 종료한다. 존재하지 않는 기능을 정상 서비스처럼 보이게 하지 않는다.

## 7. 배포 강제 검증
- 모든 등록 하위서비스는 공개 경로와 관리자 경로의 운영 배포 probe를 가져야 한다.
- CI는 지역 레지스트리, 라우터, 하위서비스 계약 테스트를 직접 실행한다.
- probe 또는 계약 테스트가 빠지거나 실패하면 배포 검증을 통과하지 못한다.
- 공개면과 관리자면은 각각 기대 라우팅 헤더를 확인한다.

## 8. 변경 절차
강제 형식 `ai/<agent>/<task-id>`의 격리 브랜치 → 정적 검사·계약 테스트 → staging 검증 → PR 병합 → 운영 배포 → 운영 probe 확인 순서를 따른다. 운영 서버 직접 수정은 이 절차의 대체 수단으로 사용하지 않는다.
