# EKODI 10G Capability Ecosystem Kernel

Status: runtime target kernel, not a constitutional generation amendment.

## Purpose

The 10G kernel turns repeated EKODI work into governed reusable capability candidates without granting AI new sovereign authority.

The operating loop is:

`Experience -> Pattern -> Automation Candidate -> Sandbox/Eval -> Capability Proposal -> PR/CI/Staging -> Guarded Promotion -> Runtime Watch`

## Cloud-first placement

- Cloudflare Control API remains the cloud control plane.
- D1 stores privacy-minimized experience fingerprints and candidate state.
- GitHub remains the immutable source, review and promotion path.
- Existing remote/cloud workers remain distributed execution nodes.
- AI providers remain replaceable reasoning providers, never authority owners.

## 10G kernel modules

- `ekodi-capability-ecosystem.js`: Capability Graph, pattern detection, candidate factory, evaluation and quarantine rules.
- `ekodi-capability-ecosystem-store.js`: append-only operational persistence.
- `ekodi-self-automation-engine.js`: scheduled closed-loop analysis and snapshots.
- `core-ai-gateway.js`: command and Pulse experience capture.
- `api-worker.js`: authenticated admin inspection and manual analysis trigger.
