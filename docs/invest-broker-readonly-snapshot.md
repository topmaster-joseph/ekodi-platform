# EKODI Invest: 증권사 조회 데이터 검증 · 대조 계층

`invest-broker-readonly-snapshot.js`는 이미 읽어 온 개인 증권계좌 정보를 서버 전용으로 검증하기 위한 **순수 함수** 모듈이다. KIS/Toss 실계좌 접속이나 주문 전송·자격증명 확인은 수행하지 않는다. 현재 기능을 실제 브로커 연결 성공 또는 장부 대사 완료로 표시하면 안 된다.

## 허용 데이터·거부 조건

- 이전에 등록한 `invest-broker-readonly-contract.js`의 공식 조회 목적지 및 실전/모의 구분을 재사용한다. KIS `paper`와 `live`를 혼합하지 않으며, Toss `paper`, IBKR 조회 통합은 별도 브로커 인증 검증 전까지 금지한다.
- 입력은 **서버에서 발급한 불투명한 UUID 계좌 참조/스냅샷 참조**만 사용한다. 계좌번호·주민등록번호·API 키·액세스 토큰·Authorization 헤더·임의 URL·비밀번호 등 추가 필드는 무조건 거절한다. 단순 UUID 형태 검증은 안전한 실제 계좌 소유권 검증이 아니며, 별도 계좌 참조-소유자 매핑을 서버에서 검증해야 한다.
- 통화는 KRW 또는 USD이며 다른 통화의 자산을 합산하지 않는다. 종목별 평가금액과 현금은 **십진수 문자열(소수점 최대 두 자리)**을 정수 최소단위로 계산한다. 숫자 지수 표기, 음수, 중복 보유종목, 불일치 총자산, 잘못된 수량, 종목별 통화 혼합을 차단한다.
- `capturedAt`은 UTC ISO-8601, 기본 최대 경과시간 5분·미래 시간 오차 30초 이내만 허용한다. 이 시간 기준은 *잔고 데이터의 수집 시각에 대한 기본 품질 검사*일 뿐, 주가의 실시간성과 증권사 공식 거래증빙을 보장하지 않는다.
- 이전/신규 잔고 비교는 동일 브로커·실전/모의 환경·불투명 계좌 참조·통화와 증가하는 스냅샷 시각인 경우에만 수행한다. 증감은 시장가치 변화·입출금·배당·수수료·주문체결 등 모든 원인이 합쳐진 수치이며 수익률로 주장하지 않는다.

## 별도 운영 보호

1. 최고관리자의 서버 검증 신원과 강한 MFA AAL2·기존 2단계 확인을 완료한다. 본인 증권계좌와 공식 API 허용 범위, 허용 출구 IP·토큰/키 Vault 상태를 실증하기 전에는 조회연동 준비 완료 처리 금지.
2. 공식 증권사 시스템과 **조회 전용 GET**로만 연결한 후, 실시간 가격의 출처·지연·통화·시각, 계좌 소유권, 계좌별 현금/보유/미체결을 독립 대조한다. KIS처럼 GET에 필수 조회 매개변수가 있는 경우, 클라이언트의 임의 query 문자열을 허용하지 말고 별도 검증된 서버 전용 요청 생성기를 작성한다.
3. 이 순수 모듈은 항상 `sourceAuthenticated:false`, `ownerBindingVerified:false`, `connected:false`, `readOnlyConnectionVerified:false`, `networkCallPerformed:false`, `liveOrdersEnabled:false`로 반환한다. 실제 증권사 검증 증거를 보유한 이후에도 해당 증거는 **별도 신뢰된 서버 모듈**에서 기록·감사한다.
4. 조회 결과에 실시간 자금 거래나 투자자문을 결부하지 않는다. 현재 자동매매 전역 차단과 `POST /live/orders` HTTP 423, 60일 모의 운용 및 별도 실주문 승인 의무 유지.
