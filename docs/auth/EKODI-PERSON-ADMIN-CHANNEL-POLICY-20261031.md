# EKODI 통합 회원과 관리자 권한 운영 계약 (2026-10-31)

## 원칙
사용자가 접속하는 채널(홈페이지, 앱, QR, YouTube·소셜 링크, 외부 브랜드 도메인)과 로그인 공급자(Google, Kakao, Naver, 검증된 이메일 등)는 **EKODI Person의 출입구**일 뿐 별도 회원 본체가 아니다.

- `https://ekodi.kr/auth/`는 사용자 인증 입구이고, `login_identities(provider,provider_subject)`는 검증한 외부 신원을 `people.id` 및 `people.ekodi_id`에 연결한다.
- 공개 사용자 페이지는 비로그인 열람 가능. 글쓰기, 회원기능, 주문, 개인정보, 구독, 자금 거래는 서버의 인증/결제 정책을 통과해야 한다.
- 여러 로그인 수단의 **이메일이 같거나 이름이 같다는 이유로 같은 Person으로 자동 합치지 않는다.** 기존 로그인 세션 + 새 공급자 재인증 + nonce/state + 미연결 확인 + 명시적 연결, 충돌하면 별도 검토.
- 로그인 수단이 달라져도 **승인된 동일 Person**의 회원등급·사이트 역할·공간은 한 번만 관리한다. 불확실한 공급자·유효하지 않은 세션·연결 해제·취소된 권한은 즉시 거부한다.

## 관리자 권한은 로그인과 별도
1. EKODI는 공급자 서명·발급자/대상/만료·nonce와 세션, 해당 공급자의 불변 `sub`를 검증해 신원증명.
2. 서버는 해당 `auth_user_id`가 `login_identities`에 활성 연결된 EKODI Person인지 확인.
3. **사이트 관리자는** 서버의 해당 `tenant_id/site_key`와 `role/status`가 활성 상태인지 확인. 승인된 동일 Person의 연결 로그인은 동일 권한을 사용할 수 있지만 서로 다른 사이트나 다른 사람의 권한을 상속하지 않는다.
4. **플랫폼 최고관리자는** 서버 등록 플랫폼 역할(`profiles.platform_admin` 또는 기존 보호된 recovery allowlist)뿐 아니라 같은 Person의 검증된 Google 신원이 있어야 한다. 이 조건은 현재 로그인 수단이 Google인지와 별개다. 보호된 최고관리자 행정 작업은 `/admin/`에서 Google `sub` pinning 및 재인증/step-up을 추가로 요구한다.
5. 기존 운영자 인증 D1 `admin_google_accounts`와 사용자 Supabase Person 원장은 **현재 별도로 관리**된다. D1의 관리자 세션은 자체 고유 인증으로 보호되어 있으며, 두 DB 간 인가·로그아웃·역할 동기화까지 완전히 통합되었다고 선언해서는 안 된다. 단일 화면·단일 원장을 향한 단계적 전환과 운영 실증이 필요하다.
6. 사용자 `display_name` 및 신뢰할 수 없는 `user_metadata`, 이메일 문자열 단독, 브라우저/채널 ID는 권한 근거가 아니다. UI에 관리자 버튼이 보여도 API에서 권한 검증을 다시 한다.
7. 권한 변경은 서버에서 주체/시각/대상/역할/기능 단위로 감사하고, revoke·세션 취소·MFA 실패·타 Person 충돌은 즉시 거부한다. 초고위험 결제·보안·사용자 변경은 단시간 승격 및 Google 계정 재확인.
8. 계정 회복·임의 Person 병합이나 구독·결제 병합은 관리자 권한 부여와 별개다. 인증 성공이 개인정보 이동·플랫폼 관리자 승격 또는 중복청구 승인으로 이어져서는 안 된다.

## 현재 구조 확인 및 제약
- 저장된 플랫폼 관리자 프로필 4건과 활성 플랫폼 권한 등록 2건은 2026-10-31 시점 운영 DB의 **집계 점검에서** Google 검증 신원과 연결되어 있었다. 이 수치는 고유 관리자 수가 아니다.
- 이 PR은 `access-api`의 최고관리자 증명 및 연결된 사용자 신원의 사이트 역할 적용을 강화한다. 사용자 전체 37개 사이트의 로그인 E2E/브라우저 검증과 D1 관리자 세션의 Person 원장 전환은 **별도 후속 출시 조건**이다.
- 기존 Google 로그인과 D1 관리자 인증, 서비스별 업무/결제/구독 데이터는 이 변경으로 수정하지 않는다.

## 검증 가드
- 허가되지 않은 이메일·다른 Person·카카오 미검증 이메일·연결이 끊긴 Google ID가 플랫폼 권한을 받을 수 없어야 한다.
- 최고관리자 역할이 없는데 Google 로그인을 했다는 이유만으로 관리 권한을 받을 수 없어야 한다.
- 같은 Person의 두 인증수단으로 사이트에 접근하면 해당 사이트에만 동일한 역할, 다른 사이트는 403.
- 로그인 시작 사이트·하위 경로·쿼리 복귀, 비회원 공개 열람, 관리자 권한 로그아웃·토큰 취소를 독립적으로 검증한다.
- 보호 CI/오케스트레이터 receipt/스테이징/운영 배포/실서비스 확인이 없으면 **배포 완료 표시 금지**.
