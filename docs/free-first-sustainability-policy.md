# EKODI FREE-FIRST 지속가능성 정책

## 목적

에코디 생태계의 기본 설계는 **무료 또는 무료에 가까운 경로로 핵심 기능이 계속 작동하는 것**을 우선한다. 유료 API, SaaS, AI 공급자, 외부 자동화 서비스는 편의와 확장을 위한 선택적 가속장치이며 시스템 생존의 필수조건이 되어서는 안 된다.

## 기본 규칙

1. 핵심 기능에는 무료 기본경로가 있어야 한다.
2. 유료 공급자가 없어도 읽기, 입력, 저장, 조회, 핵심 업무처리가 가능한 구조를 우선한다.
3. 외부 공급자 전용 데이터모델 대신 에코디 내부 표준 데이터모델을 먼저 만든다.
4. 유료 API 어댑터는 교체 가능하게 분리한다.
5. API 키가 존재하는 것만으로 유료 기능이 자동 활성화되어서는 안 된다.
6. 유료 기능은 별도 feature flag 또는 운영 스위치를 명시적으로 켜야 한다.
7. 사용량 증가 시 재개발하지 않도록 자동화 인터페이스와 확장 지점은 초기부터 구축한다.
8. 비용이 발생하는 동작은 관리자 화면에서 무료경로와 비용발생경로를 구분해 표시한다.
9. 외부 공급자 장애·가격변경·계약종료 시 무료 기본경로로 즉시 되돌아갈 수 있어야 한다.
10. 데이터와 감사기록은 외부 공급자가 아니라 에코디 내부 저장소에 축적한다.

## 확장 단계

### Free Core

- 무료 호스팅/무료 티어/자체 데이터 우선
- 사람이 최종 처리하더라도 핵심 업무는 중단되지 않음
- 운영비를 최소화하고 실제 사용패턴을 축적

### Assisted

- 입력 자동완성
- 템플릿
- 복사/내보내기
- 예약·알림
- 공식 무료 서비스와 연결

### Automated

- 반복량이 충분히 커지고 비용 대비 편익이 명확할 때 유료 API를 선택적으로 연결
- 자동화 공급자를 바꾸더라도 UI와 내부 데이터는 유지

### Scale

- 트래픽·사용량에 따라 유료 인프라를 단계적으로 확대
- 비용 증가가 사용자 증가 또는 수익 증가와 연결되도록 설계

## 기능별 적용 예

- 전자세금계산서: 에코디 작성·대장관리 + 홈택스 무료 직접발행 → 향후 API 자동발행
- AI: 규칙/검색/템플릿 기반 기본기능 → 외부 AI 선택 연결 → 필요 시 다중 공급자 라우팅
- 파일/문서: 자체 메타데이터와 링크 중심 → 필요 시 외부 스토리지 확장
- 알림: 관리자 화면·이메일 등 저비용 경로 → 필요 시 문자/메신저 유료 API
- 분석: 내부 로그·집계 우선 → 트래픽 증가 시 전문 분석서비스 선택 연결

## 비용 전환 기준

유료 서비스 전환은 단순히 사용자가 늘었다는 이유만으로 하지 않는다. 다음을 함께 본다.

- 월 사용량과 반복작업 시간
- 유료 API 비용
- 사람의 처리비용
- 오류 감소 효과
- 장애·종속 위험
- 향후 교체 가능성
- 수익 또는 공익적 효과 증가

유료 자동화의 편익이 비용과 종속위험을 충분히 넘어설 때만 활성화한다.

## 설계 문장

> 무료로 살아남고, 필요할 때 확장하며, 공급자가 바뀌어도 에코디는 멈추지 않는다.
