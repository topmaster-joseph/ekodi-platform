# EKODI 동행 — 공개/무료/구독형 연결 제품 계약 (2026-10-09)

## 현재 상태
- 구현 소스: [PR #3914](https://github.com/topmaster-joseph/ekodi-platform/pull/3914). 개발 브랜치 기준.
- 운영 활성화: **미승인·비활성**. 회원 프로필 수집, 실제 결제, 알선·유료 메시징 서비스가 실행 중이라는 의미가 아님.
- 원칙: 방문자는 `/singles` 소개·안전·약관을 누구나 볼 수 있다. 로그인 회원에게만 공개행사 상세·개인프로필·동행탐색을 공개한다. 개인정보와 구독 상태는 서버 측에서 확인한다.

## 기본 사용자 동선
1. 방문자: `/singles`에 공개 소개, 가치, 안전 원칙. 행사·프로필 API는 익명 요청 차단.
2. 로그인 EKODI 회원: `/singles/my`에서 19세 이상 자기확인(본인인증과 별개) 및 기본·신앙 민감정보 별도 동의, 프로필 작성.
3. 프로필은 공개 기본 OFF. 검증된 성인, 활성 동의, 본인 공개 opt-in이 충족될 때만 발견 대상이 된다.
4. 로그인 회원: `/singles/events` 행사 목록·상세 무료 확인. 행사 참가 신청은 구독 권한이 필요.
5. 로그인 회원: `/singles/discover`에서 노출 허용·성인검증 사용자만 검색, 관심 보내기 무료.
6. 상대방은 관심 수락·거절 무료. 한쪽 관심만으로 대화 생성 불가.
7. 상호 수락 후 메시지 내역은 당사자만 열람, **메시지 발송 및 답장 각각 발송자 본인의 활성 Plus 구독 검증**. 상대가 구독하지 않았다는 이유로 이미 받은 메시지 열람, 거절, 차단, 신고를 제한하지 않는다.
8. 취소·차단·신고·민감정보 동의 철회·탈퇴는 구독과 무관하게 수행 가능해야 한다.

## 구독 권한 진실과 가격
- Plan ID: `plus`. **금액/결제주기/환불 문구 미확정** — 관리자 계약 심사 전 임의의 가격·할인·구독 시도를 만들지 않는다.
- EKODI Core 결제 검증 -> 인증된 중앙 billing 이벤트 -> `singles_entitlements`에 사용자별 `source='verified_central_billing'`, `receipt_id`, `expires_at` 기록. 구매 UI에서 자체적으로 활성화하거나 user_metadata를 믿지 않는다.
- Worker `SINGLES_M1_ENABLED`, `SINGLES_SOCIAL_ENABLED`, `SINGLES_PAID_ACTIONS_ENABLED` 및 Edge `SINGLES_ONBOARDING_ENABLED`, `SINGLES_SOCIAL_ENABLED`, `SINGLES_PAYMENTS_ENABLED`는 모두 기본 OFF. 결제·회원수집·추천은 각각 심사 통과 후 제어한다.
- Premium write는 결제 비활성 시 HTTP 503, 구독 미확인·만료 시 402, 본인 및 상호동의 또는 성인확인 위반 시 403.
- 구독 만료 후에도 기존 메시지 열람(상호동의 유지 시), 거절·차단·신고 기능은 무료로 유지한다.

## 운영법 및 인권·보안 게이트
- 대한민국 결혼중개업법상 회비/수수료를 받고 결혼 상담·알선을 업으로 하는 경우 해당할 수 있으므로 국내 신고/국제 등록·계약/고지·환불 및 전자상거래 규정을 법률 검토하기 전 결제 비활성.
- 신앙·신념은 민감정보: 별도 동의, 수집 목적 제한, 철회 시 발견/전송 중단, 검색엔진 색인 차단. 교회/목회자/서비스 운영자는 원문 채팅에 포괄적인 열람 권한을 갖지 않는다.
- 미성년 접근 제한: 성인 자기확인은 본인확인이 아니며 실제 개인정보 노출·추천·행사 참가·메시지는 신뢰 가능한 `adult_verified_at` 확인이 필요하다.
- 거짓 프로필, 개인정보 추측, AI 영적 성숙도 점수, 권위에 의한 강요 및 관계 성사를 보장하는 마케팅 금지.
- 대화/추천에서 제3자 정보 노출 제한: blocked users 배제, 상호수락 검증, 서버측 소유권 검사, 속도 제한·보고/감사.
- DEV 테이블은 서비스 역할 전용, RLS 활성, anon/authenticated 직접 GRANT 없음; 운영 DB/결제 공급 연결 전이므로 운영 재현에는 실제 실증/릴리스 승인 필요.
