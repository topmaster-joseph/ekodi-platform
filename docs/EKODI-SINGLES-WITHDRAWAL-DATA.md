# 에코디 동행 — 탈퇴 데이터 처리 설계안 (초안, 승인 전)

기준일: 2026-10-25 · 상태: 1단계 구현, 2단계(물리 삭제·익명화)는 **승인 대기**

## 1. 목표
- 탈퇴 즉시 다른 회원에게 보이지 않게 하고, 재가입해도 과거 연결·대화가 되살아나지 않게 한다.
- 법정 보존 의무가 있는 기록만 필요한 기간 동안 분리 보관하고, 나머지는 보존기간이 끝나면 파기한다.
- 상대방 회원의 권리(받은 신고, 차단 등 안전 기록)를 함께 지킨다.

## 2. 1단계 — 탈퇴 즉시 처리 (구현됨, 데이터 삭제 없음)
`singles_withdraw_member(user, version)`가 하나의 트랜잭션에서 아래를 처리한다.

| 대상 | 처리 |
|---|---|
| `singles_memberships` | `status='withdrawn'`, 공개·결혼연결·신앙동의·기본동의 해제, `withdrawn_at` 기록 |
| `singles_interests` | 본인이 보낸·받은 `pending`/`accepted` 연결을 `withdrawn`으로 닫음 |
| `singles_messages` | 변경 없음. 메시지는 연결이 `accepted`일 때만 열리므로 양쪽 모두 열람·발송 불가 |
| `singles_event_rsvps` | `requested`/`approved` 신청을 `cancelled`로 바꿈 |
| `singles_consent_receipts` | `withdrawn` 영수증 추가 |

재가입하면 회원 상태는 다시 `active`가 되지만, 닫힌 연결은 `withdrawn` 그대로 남는다. 따라서 과거 대화는 다시 열리지 않는다. 같은 상대에게 호감을 다시 보내면 기존 `withdrawn` 상태를 돌려주고 새 연결을 만들지 않는다. 같은 두 사람이 다시 연결되려면 3-5의 결정이 필요하다.

## 3. 2단계 — 보존기간 후 삭제·익명화 (설계안, 승인 필요)

| 데이터 | 제안 처리 | 보존 근거·기간 | 상태 |
|---|---|---|---|
| 프로필(`singles_profiles`), 공개 카드(`singles_public_cards`) | 탈퇴 후 **30일 유예 뒤 삭제**(재가입 복구 기간) | 법정 의무 없음. 유예기간 길이는 정책 결정 | 확인필요 |
| 민감정보(`singles_sensitive_profiles`, 신앙) | **탈퇴 즉시 삭제** | 민감정보는 목적 달성 시 지체 없이 파기(개인정보 보호법 제21조) | 현재 수집 0건 |
| 메시지 본문(`singles_messages.body`) | 상대방 보호를 위해 **본인이 보낸 글은 '탈퇴한 회원의 메시지입니다'로 익명화**, 행은 유지 후 연결과 함께 1년 뒤 삭제 | 분쟁·신고 대응 필요기간은 정책 결정 | 확인필요 |
| 연결(`singles_interests`) | `withdrawn` 유지, 메시지 삭제 시 함께 삭제 | 위와 동일 | 확인필요 |
| 차단(`singles_blocks`) | **유지**(상대가 건 차단은 상대의 안전 설정) | 상대방 권리 보호 | 정책 결정 |
| 신고(`singles_reports`) | 신고자·대상 식별자 유지, 처리 완료 후 3년 보관 뒤 삭제 | 소비자 불만·분쟁처리 기록 3년(전자상거래법 시행령 제6조) 준용 여부 | 확인필요 |
| 결제(`singles_bank_orders`, `_grants`, `_audit`) | **5년 분리 보관 후 삭제**. 계좌 전체번호는 주문 시점 값이므로 보관 대상 | 대금결제·재화공급 기록 5년(전자상거래법 시행령 제6조) | 확인필요 |
| 동의 영수증(`singles_consent_receipts`) | 5년 보관 | 동의 입증 책임 | 확인필요 |
| 속도 제한 기록(`singles_rate_events`) | 이미 1일 지나면 자동 정리 | — | 구현됨 |
| 회원 행(`singles_memberships`) | 위 기록의 외래키 기준이므로 마지막에 삭제 | — | — |

### 실행 방식(제안)
1. `singles_purge_due()` 함수를 만든다. 보존기간이 끝난 행만 지우거나 익명화하고, 처리 건수를 감사 테이블에 남긴다.
2. 처음에는 수동 실행 + 실행 전 건수 미리보기(dry-run)로 운영한다. 자동 실행 여부는 EKODI 운영 정책에 따른다.
3. 외래키 `ON DELETE CASCADE`가 걸린 테이블(프로필, 신고, 차단, RSVP)은 회원 행 삭제 시 함께 지워진다. 결제·메시지처럼 보존해야 하는 기록이 회원 행 삭제로 사라지거나 막히지 않도록 삭제 순서를 함수 안에서 고정한다.

## 4. 승인·결정이 필요한 항목
1. 프로필 유예기간(제안 30일)
2. 메시지 익명화 방식과 보관기간(제안 1년)
3. 신고·결제·동의 기록 보존기간을 위 법정 기간으로 확정할지(법률 검토)
4. 동행 서비스가 결혼중개업에 해당하는지에 따른 추가 보존 의무(법률 검토)
5. 같은 두 사람이 탈퇴·재가입 후 다시 연결될 수 있게 할지. 허용하려면 과거 메시지를 먼저 삭제한 뒤 새 연결을 만들어야 한다.
6. 개인정보 처리방침·동행 개인정보 안내 문안에 위 기간 반영

## 5. 참고(확인 기준)
- 개인정보 보호법 제21조(개인정보의 파기): 보유기간 경과·목적 달성 시 지체 없이 파기. 구체적 일수는 확인필요.
- 전자상거래 등에서의 소비자보호에 관한 법률 시행령 제6조: 계약·청약철회 5년, 대금결제·재화공급 5년, 소비자 불만·분쟁처리 3년, 표시·광고 6개월. 원문은 국가법령정보센터에서 최종 확인 필요.
