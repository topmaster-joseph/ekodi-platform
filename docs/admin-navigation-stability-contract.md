# EKODI 관리자 메뉴 안정화 계약 (ADMIN-NAV-STABLE-001)

## 목적
대규모 메뉴 개편을 반복하지 않고 서비스 등록표와 사이트별 표시 정책의 투영만 갱신한다.

## 고정 경계
- 플랫폼 최고관리자: 정식 플랫폼 `/admin`에서 `admin-menu-registry.js`의 업무 분야별 통합 서비스를 관리한다. 모든 서비스 열람과 실제 실행 권한은 다르다.
- 사이트 관리자: 각 사이트의 canonical `/{site}/admin` 하위에서 독립 `서비스설정` + 권한에 맞춘 단일 `업무메뉴`를 본다. 공통/전용의 내부 코드 분류를 UI에 복제하지 않는다.
- 사이트 선택 후 `/services` 진입은 권한이 있는 관리 대상에 한한다. 서로 다른 사이트의 데이터/권한을 합치지 않는다.
- 서비스설정: 기존 `tenant_site_service_catalog`의 분야별 항목을 사용한다. 각 항목의 표시 설정은 해당 tenant의 감사 가능한 설정으로 저장한다.
- 사이트 유형별 기본 구성 및 추천은 앞으로 별도 스키마를 늘리기 전에 기존 카탈로그와 정책을 재사용하고, 사용자의 결정 없이 유료 계약/계좌 연동/방송 실행/권한 상향을 수행하지 않는다.
- 준비 중 서비스는 활성화를 막는다. 메뉴 숨김은 데이터 삭제나 직접 URL 접근 권한 박탈의 대체물이 아니다. 서버 측 인증/권한 검사를 반드시 유지한다.

## 변경 가드레일
1. 단일 등록표/단일 canonical URL/동일한 메뉴 ID 사용; 중복 메뉴와 별도 Sidebar 구현 금지.
2. 새 서비스는 카탈로그에 등록하고 필요 사이트에만 노출. 메뉴 전체 레이아웃 재작성 금지.
3. 변경 전후 역할별 메뉴 투영, 하위 사이트 분리, 사이트 전환, 저장/새로고침, 준비 상태, PC·모바일 화면을 검증.
4. 등록표 수정에 회귀 테스트를 수반하며, 운영 기능 확인 전 완료라고 주장하지 않는다.
5. 기존 겹치는 PR은 EKODI 오케스트레이터 충돌 가드에서 직렬화·정리한다.
