# 사이트별 메일 수집과 문서 발행

**작업 상태:** 사이트별 Gmail 문서 수집·관리자 대장·매출확인서·원본 메일 미리보기는 중앙 소스에 반영되었다. 실제 메일 계정 연결, 한국전력 거래증빙 검증 및 국세청 전자세금계산서 발행은 별도의 실증이 필요하다.

## 기능 경계

1. 에코디 메일 관리의 사이트별 소유·접근 권한 모델을 그대로 사용한다. 기관 메일은 연결된 해당 사이트의 관리 및 읽기 권한이 있어야만 문서 발행 규칙에 연결된다.
2. 새 '문서 발행' 탭에서 Gmail 계정·검색어·기간(월 중 시작일/종료일)·요청 문서 유형을 정한다.
3. 현재 API Worker의 정기 실행은 한국 시간(Asia/Seoul)을 기준으로 요청 메일을 검색한다. 수동 확인도 가능하며 매일 1회 이상 성공한 규칙은 중복 조회하지 않는다.
4. 메일 제목·발신자·수신시각 등 최소 메타데이터만 보관한다. 메일 본문과 Google OAuth 토큰은 새 문서 테이블에 보관하지 않는다.
5. 메일 발견은 REVIEW 상태의 '발행 요청'만 만든다. 외부 메일의 금액이나 발신자가 자동으로 증빙되지 않으며, 공급자와 상대방, 거래기간, 실제 매출액, 세액 및 증빙 식별자를 관리자가 확인하고 승인한다.
6. 자체 '매출확인서'는 승인 이후에만 내부 고유 문서번호를 부여하고 인쇄용 문서를 제공한다. 이는 국세청 전자세금계산서나 금융기관 매출증명서가 아니다.
7. 세금계산서 요청의 법적 발행은 기존 에코디 Finance·홈택스·계약된 발행대행 경로를 이용한다. 이 구현은 국세청 송신·승인번호를 임의 생성하지 않는다.
8. 과금 API 자동 활성화, 무인 세금계산서 전송, 타 사이트 자료 열람은 금지된다.

## 2026-11-13 메일 누락 방지 후속

- 자동 수집 검색은 이제 **받은편지함과 보관처리된 일반 메일**을 함께 검색한다. 일반 메일함 화면은 기존 받은편지함 필터가 기본값으로 유지된다.
- Cloudflare Workers 무료 플랜의 외부 호출 한도를 고려하여 **한 번의 실행에서 최대 12개 Gmail 메일 상세정보만 확인**한다. Gmail 페이지가 남으면 암호화된 OAuth 정보가 아닌 불투명한 이어받기 커서만 사이트별 D1 원장에 보관한다.
- 정기 실행기에서는 **한 번에 한 사이트의 한 규칙만** 진행하고, 가장 오래 점검되지 않은 규칙부터 공평하게 처리한다. 다음 10분 주기에 이어서 읽고, 마지막 페이지 도달 시에만 한국 날짜 기준 '전체 점검 완료'를 기록한다.
- 읽기 오류나 인증 실패가 발생하면 커서를 유지하고 오류를 표시하며 안전하게 재시도한다. 커서가 만료되면 사이트 관리자는 **처음부터 다시 점검**으로 커서만 초기화한다. 메일 메시지 ID 기준 중복 접수는 방지되고 기존 승인 이력은 보존된다.
- 사이트 관리자는 매출확인서 외에 **전자세금계산서 요청**도 수동으로 접수할 수 있다. 직접 접수는 발행이 아니며, 국세청 전송은 계속 별도 인증된 Finance 경로만 가능하다.
- 비활성화된 메일 규칙은 수동 동기화 API에서도 실행되지 않는다. 규칙의 감사기록과 이미 접수된 요청은 보존한다.
- 인증되지 않은 문서 API 호출은 DB 스키마 초기화 이전에 거부한다.

- 인증된 직접 메일 조회 역시 동일한 12건 상한을 적용하고, 더 볼 내용이 있으면 사용자에게 이어받기 상태를 표시한다.

## 2026-11-14 KST 기간 경계에서 검색 이어받기

- Gmail 검색 페이지가 월별 수집 종료일(예: 25일)까지 끝나지 않으면 사이트별로 저장한 커서가 남아 있는 한 **26일 이후에도 완료될 때까지 계속 수집**한다.
- 신규 검색은 설정된 월별 수집 기간에만 시작한다. 기존 커서가 없는 규칙은 기간 밖에서 시작하지 않는다.
- D1 SQL에서 `workspace_id`와 `rule_id`를 모두 일치시켜 미완료 검색의 사이트 간 혼합을 방지한다. 비활성화된 규칙은 이어받기도 하지 않는다.
- 완료가 확인된 마지막 페이지에서만 수집 완료 날짜를 기록한다. KST 자정·월말을 넘는 단위 테스트와 보호된 CI를 릴리스 조건으로 한다.

## 2026-11-14 원본 요청 메일 확인

- 사이트별 문서 발행 대장의 **원본 요청 메일 확인** 버튼은 해당 사이트 메일 계정이 연결된 Gmail 수신 요청에만 표시한다. 직접 등록된 요청에는 버튼이 없다.
- 관리자는 기존 `/api/mail/control/accounts/:accountId/messages/:messageId`의 별도 권한 검사를 통과해야 원본 메일 본문·첨부파일 목록을 읽을 수 있다. 기존 수신자·읽기 권한을 우회하지 않는다.
- 메일 본문은 브라우저에서 `textContent`로 렌더링하며 HTML로 해석하거나 새 발행문서 DB에 복사하지 않는다. 첨부파일은 이름 목록만 표시한다.
- 확인 내용이 계약·계량·지급내역과 일치해야 담당자가 별도의 증빙 승인 작업을 수행한다. 메일 미리보기만으로 전자세금계산서가 발행되지는 않는다.

## 2026-11-14 발행 승인 전 Gmail 원본 재검증

- Gmail에서 수집된 문서 요청의 **승인 시점**에 원본 메시지 ID로 Gmail 메타데이터를 한 번 더 조회한다. 사용자는 먼저 문서 대장의 원본 메일을 확인하고 거래내역을 대조해야 한다.
- 재검증은 해당 사이트의 원래 메일 계정에 대해 승인 담당자에게 **읽기 권한**이 있는지, Gmail OAuth 연결과 읽기 동의가 살아 있는지 확인한 다음 진행한다.
- 원본의 메시지 ID·발신자·제목·날짜가 수집 때의 메타데이터와 다르거나 메일을 다시 읽지 못하면 **승인이 실패**한다. 이미 저장된 요청·증빙·승인 이력은 변경하지 않는다.
- 수동 등록된 요청에는 Gmail 원본이 없으므로 기존 증빙·관리자 승인 경로를 유지한다.
- Gmail 발신자 문자열 일치만으로 한국전력의 법적 신원 또는 금액을 입증할 수는 없다. 계약, 계량, 정산내역, 사업자 정보 등과 별도로 대조해야 한다. 법적 세금계산서 발행은 EKODI Finance/홈택스에서 별도 승인·전송한다.
