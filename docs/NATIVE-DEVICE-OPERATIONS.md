# EKODI 자체 PC 실행 노드 운영

EKODI의 상시 운영 경로는 **Windows EKODI Device Agent → HTTPS(외향 연결) → EKODI Control API → D1 작업 큐 → 결과/감사 기록**이다. 외부 원격 서비스는 설치와 장애 조사에만 선택적으로 활용하고, 상시 작업 실행의 필수 의존성으로 사용하지 않는다.

## 컴퓨터 설치와 인증
- 관리자 `https://ekodi.kr/admin/status/devices`에서 일회성 등록 코드를 생성한다.
- 각 컴퓨터에서 정식 Windows Agent를 등록한다. 관리자 승인과 코드 없이 장치 토큰을 임의 발급하지 않는다.
- 등록된 Windows Agent는 전원 켜짐·로그인 상태에서 자동 시작되어 클라우드에 60초 주기로 하트비트를 보내고, 작업을 받아 허용된 명령만 수행한 뒤 결과를 서버에 반환한다.
- 별도 프로필의 Chrome/Edge 백그라운드 브라우저는 카나리 검증 후에만 사용한다. Hyper-V 가상화는 해당 PC의 지원·권한 확인 후 별도로 활성화한다.

## 비용과 장애 복구
- EKODI 자체 에이전트·브라우저 실행에는 Desktop Commander 월별 원격 호출량 제한이나 유료 원격 릴레이가 필요 없다.
- 정상 유휴 상태의 명령 조회 주기는 20~24초로 분산하고, 명령 실행 직후에는 3초로 줄인다.
- 일시적 통신 실패, 401/403 인증 오류, 429 제한 오류는 15~300초의 지수 백오프로 보호한다. 실패 사유 분류만 `%ProgramData%\EKODI\DeviceAgent\runtime-status.json`에 저장한다.
- 로컬 로그·상태에는 토큰이나 요청 본문을 저장하지 않는다. HTTP 인증이 없으면 작업을 수신하지 않는다.
- Cloudflare 요청/저장 용량, 네트워크·전기요금, 유료 AI API는 별도 비용 요소이며 무조건적인 0원 운영을 보장하지 않는다.

## 실증 범위
- Windows PowerShell 5.1에서 System.Net.Http 로딩 및 ProgramData 환경 변수가 없을 때의 복구를 자동 검사한다.
- user3에서 Chrome 자체 카나리와 실제 EKODI 공개 페이지 검사를 실행하여 HTTP 200, 임시 프로필 및 화면 증거 삭제를 확인했다.
- 중앙 인증을 이용한 작업 배정→수행→결과 보고는 PC마다 최초 정식 등록 후 별도 실증해야 한다. 원격 외부 서비스의 온라인 표시는 EKODI 자체 등록 증빙이 아니다.
