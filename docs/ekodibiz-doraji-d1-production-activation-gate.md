# 도라지 업무원장 D1 운영 활성화 승인 게이트

현 단계: `schemas/ekodibiz/doraji-draft-ledger.sql`은 **스키마 보관·검토본**이다. `migrations/`에 넣거나 운영 D1에서 실행하지 않는다.

## 승인 이전: 안전하게 자동 진행 가능한 작업
1. `node --test test/ekodibiz-doraji-ledger-api.test.mjs test/ekodibiz-doraji-ledger-sqlite.test.mjs test/ekodibiz-doraji-ledger-isolated-e2e.test.mjs`로 익명 접근 차단, 관리자 검증, 프로젝트 간 격리, 열람자 쓰기 차단, 낙관적 버전 충돌, 변경 감사의 SQLite 증거 확보.
2. `node scripts/validate-additive-migrations.mjs`와 공식 변경 충돌·보안·스테이징 검사를 통과한다.
3. 읽기 전용 운영 스키마 검사로 `admins`, `doraji_*`, 외래키 의존성 및 기존 데이터의 안정성을 확인한다. 기존 회계·결제·회원·게시판 테이블은 수정하지 않는다.
4. D1 백업이 실제 생성됐고 동일 구조의 격리본으로 복원 가능한지 증거를 남긴다. 실패하면 배포·활성화를 중단한다.
5. 운영 D1 예상 쿼리 수, 백업 용량, 복원 비용 및 Cloudflare 할당량을 점검한다.

## 최종 승인 후에만 가능한 작업
1. 검증된 정확한 스키마 SHA, 백업 식별자, 담당 운영자와 운영 창구를 승인 기록에 연결한다.
2. 보호된 마이그레이션 실행기를 통해 *선별한* 도라지 스키마 파일만 운영 D1에 적용한다. 다른 미적용 마이그레이션을 일괄 실행하지 않는다.
3. `PRAGMA foreign_key_check`, 네 개 테이블과 인덱스 존재 여부를 읽기 전용으로 검사한다.
4. 운영에서 허용된 관리자 계정으로 프로젝트 한 건을 생성·수정·열람하고, 타 계정 격리와 401/403/404/409, 감사 기록, 계약/결제 미실행을 실증한다. 테스트 자료는 외부 고객·실제 거래 내역이 아니다.
5. 관리자 로그인 복귀, PC·모바일 화면, 모든 메뉴, 초안 등록·수정 및 통합 보고를 검증한다. 실패하면 쓰기를 중단하고 백업/정상 상태 복구 절차를 따르며 스키마 삭제를 자동 실행하지 않는다.

**비활성화된 기능:** 계약 서명, 검수/정산 확정, 돈 송금, 세금계산서 발행, 권한 자동 위임, 외부 데이터 전송. 이 문서만으로 실제 운영 DB 적용 승인이 발생하지 않는다.
