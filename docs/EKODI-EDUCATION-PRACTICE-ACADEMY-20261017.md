# EKODI Education · 맞춤형 실습강의실 및 온라인 컨설팅 통합안 (2026-10-17)

## 1. 제품 결정
- 정식 진입: `https://ekodi.kr/edu/`; 실행 소유자는 **기존 독립 Education Worker**, 자산 경로는 `education/`.
- 새 진입: `/edu/study/academy/` (Worker 안에서는 `/study/academy/`). **새 앱, 새 도메인, 인증 경계, 운영 DB를 만들지 않는다.**
- 기존 목포대 교직원 AI부트캠프 `/edu/study/ai-bootcamp/`, 자료 편집실, 강사 서류 편집실, `/learn/` 학습 기반, 청계면 소상공인 수요조사 `/cgma/ai-education/`는 보존한다.
- 무안군민 교육은 지역주민 트랙에 포함하되 지역 기관의 실제 위탁 계약·대상·일정은 별도 확정한다.
- 모든 최상위 교육 설계 화면은 강사/사용자 페이지 우선. 관리자는 권한이 있는 사용자 화면 안에서 수정·관리하며 별도 관리자 메뉴를 증식하지 않는다.

## 2. 실제 구현 범위 (PR 제안 / 운영 배포 전)
1. 소상공인, 교직원, 지역주민(무안군민), 재직자, 학생의 **5개 대상 프리셋**, 각 4개 실습모듈과 검증기준.
2. 지원사업명·의뢰기관·과정명·주제·회차별 사용자 지정 커리큘럼·성과지표·기간·온라인/대면/혼합·회차(1~24)·수업시간(40~240분)·실습비중(40~85%)에 따른 강의안 생성.
3. 회차별 강사 화면, 발표 모드, 키보드 화살표 전환, 복사 가능한 안전한 AI 실습 지시문, 실습메모 및 결과 자가점검.
4. 강의계획서 Markdown, 과정설정 JSON, 실습 기록 Markdown 내보내기 및 과정설정 JSON 재가져오기 (파일은 브라우저에서만 처리).
5. 교육 도입/현장 실습/기관 지원사업 설계/사후 코칭의 **4개 온라인 컨설팅 안내 유형**, 제출 전 문의 초안 작성·복사.
6. 기존 Education 홈과 Study 페이지에서 통합 강의실에 진입.

## 4. 학습·컨설팅 운영 흐름
- **사업 담당자/강사:** 문의 접수 → 교육 대상·난이도·환경 및 지원사업 기준 입력 → 자동 강의구성 초안 → 담당자 검토/확정 → 강의실 자료 준비.
- **교육생:** 공개 설명/일정 열람 → 필요 시 인증 후 수강신청 → 강의/실습/성과물 제출 → 검증/피드백 → 수료/사후 학습.
- **컨설팅 고객:** 공개 안내 → 유형/목적 입력 → 신청서 초안 → 향후 보안된 접수·상담예약 → 계약/결제(해당 시) → 결과보고 및 후속 코칭.
- 특정 지원사업의 공고·모집조건·수료기준·지원액 등은 공고 원문 확인 전 확정사실로 표시하지 않는다.

## 5. 보호 규칙과 출시 게이트
- Google/EKODI는 인증만 공유. 기존 로그인 시작 URL로 복귀. 승인 전 회원·수강생 정보, 출결, 점수, 여권, 연락처, 원본 강의서류를 공공 자산에 저장하지 않는다.
- 현 PR은 정적·가상데이터 프런트엔드다. 로컬 입력은 네트워크로 제출되지 않고 페이지를 닫으면 사라진다. 실제 온라인 상담 예약이나 실시간 송출 기능을 구현했다고 표시하지 않는다.
- 신뢰할 수 없는 JSON 파일은 형식·크기·필드 범위를 확인하고 실제 서버 발행·DB 변경에 사용하지 않는다.

- 이 PR의 브랜치 커밋을 공식 오케스트레이터가 검토·승격해야 하며 필수 CI·보호된 병합·스테이징·운영 배포를 우회하지 않는다. **실서비스 실증 증거 확보 전 배포완료라고 말하지 않는다.**
