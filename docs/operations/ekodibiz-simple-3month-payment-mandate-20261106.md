# EKODIBIZ — 기간 직접입력형 AI 구매·결제 위탁 운영안

> 이 문서는 2026-11-06 최초 3개월 운영안의 후속 개정입니다. 변경 추적: 이슈 #8791 (2026-11-08). 과거 파일명은 기존 문서 링크의 연속성을 위해 유지합니다.

## 범위와 계약 당사자
- **사업 및 계약 주체:** 에코디비즈 개인사업자. 별도 PG 사업자/법인/도메인을 신설하지 않습니다.
- **고객:** 기관 또는 개인. 어느 유형이든 신청자가 **계약기간 개월 수를 직접 입력**합니다. 기본값은 없고, 기술·데이터 보호 상 1~120개월 범위의 정수만 접수합니다.
- **기존 계약:** 기존에 저장된 1개월·3개월 계약의 기간, 확정 견적, 결제기록을 소급 수정하지 않습니다. 새로운 신청의 개월 수가 최초 계약 상태로 저장됩니다.
- **금액:** 에코디비즈 위탁료와 공급사 구독료 예산을 별도로 견적, 승인된 공급사 수납범위 밖의 구독료 수납은 금지합니다.
- **기간:** 공급사의 실제 이용 개시를 업체 관리자가 확인한 시점에 신청한 개월 수만큼 위탁관리 종료일을 산정합니다. **위탁관리 기간 종료는 공급사 자동갱신 해지가 아닙니다.**
- **결제:** 실제 거래는 PG·공급사·규제 승인 및 운영 사전조건을 모두 충족한 경우에만 활성화합니다. 현재 코드의 수동 증빙 기록은 실제 결제를 실행하지 않습니다.

## 역할별 고유 주소와 정본 메뉴
| 표기 | 정본 주소 | 기능 및 보호 |
|---|---|---|
| 위탁신청 | `/ekodibiz/ai-agency/apply` | 기관/개인, 원하는 계약 개월 수 입력, 견적 신청 |
| **계약 담당자** | `/ekodibiz/ai-agency/university` | 신청번호와 비밀 조회코드로 **그 계약만** 조회. 기존 URL을 깨뜨리지 않기 위해 `university` 경로를 유지하지만 대학만의 계약으로 제한하지 않음 |
| 개인 신청 | `/ekodibiz/ai-agency/individual` | 개인 유형 기본 선택. 개월 수는 빈칸으로 두고 직접 입력 |
| **업체 관리자** | `/ekodibiz/ai-agency/manage` | 관리 키를 통한 검토·견적·서비스 개시·결제증빙·정산·갱신중단 확인 |

- 각 페이지의 메뉴에 동일한 역할 이름을 표시하고, 링크 공유는 정본 주소만 사용합니다.
- 계약 조회 권한은 URL 자체가 아니라 **신청번호와 개별 비밀 조회코드** 검증으로 부여됩니다. 보안코드를 쿼리스트링·공유 URL에 넣지 않습니다.
- 업체 관리자 API는 기존 서버 운영자 인증키로 보호합니다. 브라우저 저장소에 키를 저장하지 않습니다.
- `/ekodibiz/ai-agency-admin` 이전 링크는 `/manage`로 정리합니다. 플랫폼 공통 `/admin` 셸과 충돌시키지 않습니다.

## 1건의 계약·월별 증빙·종료 처리
1. 계약 담당자가 기관/개인, 공급사, 서비스, **계약기간 1~120개월 중 정수**를 선택해 신청합니다. 가격·카드·비밀번호·OTP는 신청자가 보내지 않습니다.
2. 업체 관리자는 공급사 허가와 위탁범위를 확인하고 별도의 위탁료 및 구독료 예산을 견적합니다.
3. 계약 담당자는 확정된 범위·기간·금액을 조회하고 동의합니다. 실제 PG 결제는 승인된 범위에서만 가능합니다.
4. 공급사의 실제 서비스 개시를 확인하면 **입력한 개월 수**만큼 위탁관리 기간을 산정합니다.
5. 실제 공급사 영수증의 **월차 1부터 계약기간의 마지막 월차까지** 회차·금액·지급일·식별번호를 수동 기록할 수 있습니다. 이미 등록한 회차, 영수증 중복, 계약 개월 수 초과 및 공급사 예산 초과는 서버에서 거절합니다.
6. 공급사의 갱신중단을 독립적으로 확인하면 취소·갱신중단 확인번호만 기록하고 기존 개인 AI 계정/대화는 삭제하지 않습니다. 관리 종료로 자동 해지했다고 표시하지 않습니다.
7. 조회권자는 본인 계약의 수동 증빙 요약과 CSV를, 업체 관리자는 계약별 수동 정산 요약 CSV를 확인할 수 있습니다. 미배정 예산은 은행 잔액이나 확정 환불액이 아닙니다.

## API / 데이터 계약
- `POST /api/agency/apply`: `months`는 **JSON 정수 1~120 필수**. 서버의 유형별 1·3개월 강제값 사용 금지.
- `POST /api/agency/status`: 조회코드 검증 후 `record.months`와 계약기간 길이에 따른 `campus.periods`를 반환. 필드명 `campus`는 기존 호출자 호환을 위해 유지하고 다른 계약의 개인정보·인증정보는 노출하지 않습니다.
- `POST /api/agency/admin/settlement`: 기존 계약별 수동 증빙과 `months`를 반환.
- `POST /api/agency/admin/record-cycle`: 해당 계약의 `1 <= cycle <= record.months` 검사, 중복 회차·식별번호·예산 초과 거절.
- `POST /api/agency/admin/stop-renewal`: 독립 검증한 외부 공급사 중단 증거를 **기록만** 합니다.
- `POST /api/agency/admin/activate`: 기록된 선택 개월 수로 관리 종료일 계산. 기존 확정기간을 임의 변경하지 않습니다.

## 사업·법무 필수 게이트
- 국내 PG 계약/등록 필요성, 해외 결제/외국환 의무, 공급사의 제3자 결제/수납 허용 여부를 각각 공식 기록으로 확인해야 합니다.
- 구두 동의 또는 위탁계약이라는 명칭만으로 외부 공급사 대납·재판매 허용이나 PG 등록 면제가 확정되는 것은 아닙니다.
- 실결제 활성화 플래그 `AGENCY_LIVE_ENABLED`, `AGENCY_PG_SCOPE_VERIFIED`, `AGENCY_SUPPLIER_COLLECTION_VERIFIED` 및 PG 비밀키/서버권한은 이번 변경에서 **일절 수정하지 않습니다**.
- 실결제 시작 전 보관·감사기록, 세금계산서, 취소·환불·환차손 책임, 계약별 적법 수납범위와 고객 승인 증빙을 별도로 확인합니다.
