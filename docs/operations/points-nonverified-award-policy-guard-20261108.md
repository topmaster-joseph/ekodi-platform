# EKODI Rewards V2 — 비검증 활동 포인트 차단 (#7778 / #6739)

**상태: 보안 코드 제안. 운영 DB에 자동 적용하거나 포인트 기능을 활성화하지 않는다.**

## 막아야 할 근거

- 레거시 `ekodi_points_active_heartbeat`는 서버 시간으로 간격을 측정해도 **foreground/최근 상호작용** 신호 자체는 브라우저가 보낸 값이다. 실제 수강 완료, 승인된 판매/콘텐츠, 서버 검증된 활동 증거와 다르다.
- `devotion_self_report`는 개인의 신앙 활동 자기신고다. 신앙의 깊이, 예배·묵상 기록을 금전 가치가 있는 포인트로 평가하거나 보상하지 않는다.
- 기존 기본값이 비활성화여도 운영자가 실수로 활성화할 경우, 앱 표시뿐 아니라 데이터베이스 정책 자체가 거부해야 한다.

## 안전한 구현

- `20261108224500_ekodi_points_nonverified_reward_guard.sql`은 **현재 enabled 상태의 레거시 규칙이 있으면 먼저 오류로 중단**한다. 기존 원장·지갑·증빙·사용자 자료를 삭제하거나 수정하지 않는다.
- `ekodi_point_rules`에서 `rule_id='active'`와 `enabled=true`의 동시 사용을 금지한다. 기존 RPC와 내부 `award_activity`는 활성화된 해당 규칙을 조회해야 하므로 양쪽이 차단된다.
- `ekodi_point_evidence_adapters`에서 `adapter='devotion_self_report'`와 `enabled=true`의 동시 사용을 금지한다. 미활성 기록 정의는 보유할 수 있으나 경제 보상은 발생하지 않는다.
- 검증된 비종교적 활동·교육 수료·운영자 승인 콘텐츠에 대한 적립 규칙 및 사이트별 상한·중복 방지는 유지한다.

## 운영 적용 전 승인 게이트

1. 운영자/법무·재무·보안이 약관·전환/기부 가능성·서비스별 적용 범위를 확인한다. 별도 승인이 없으면 적립·전환·기부를 활성화하지 않는다.
2. 지정된 Shared Drive의 상속 ACL을 실증하고, 사용자 소유 age 암호화 키·실제 백업 파일·해시 읽기·격리 복원·독립 이중서명을 완료한다.
3. 마이그레이션은 보호된 별도 Supabase 배포 프로세스로만 실행한다. 기존에 이 두 규칙이 활성화되어 있었다면 실패가 정상이므로 데이터를 자동 비활성화하지 말고 승인된 이행안을 준비한다.
4. 로컬 throwaway DB에서 전체 SQL 스모크와 무결성·RLS·롤백 잔여 0건을 실증하고, **운영에서는 포인트 테이블/Edge Function 승격 이후** 별도 가드 및 synthetic 테스트를 수행한다.
5. `POINTS_ENABLED=false`는 서비스 운영 승인이 날 때까지 유지한다.

**되돌리기:** 이 변화가 환경과 충돌하면 초기 배포를 보류한다. 기존 보호된 흐름에서만 해당 두 제약을 검토·제거할 수 있으며, 실서비스 활성화나 과거 포인트 보상을 소급 적용하지 않는다.
