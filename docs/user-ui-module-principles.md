# EKODI 사용자 UI 모듈 원칙

상태: 표준
버전: v2
적용 대상: EKODI 생태계의 사용자 화면(`public`, `workspace`)

## 1. 핵심 원칙

EKODI의 사용자 화면은 공통 상단 헤더와 공통 하단 푸터를 하나의 공유 UI 계층으로 상속한다.

- 사용자 화면의 상단 헤더는 스크롤과 무관하게 화면 상단에 고정한다.
- 헤더의 제목, 서비스명, 공간명처럼 중심을 이루는 텍스트는 화면 중앙축을 기준으로 중앙 정렬한다.
- 중앙 정렬 원칙은 **헤더 영역에만** 적용한다.
- 헤더 아래의 본문, Hero, 카드, 목록, 폼, 표, 콘텐츠 정렬은 각 사이트의 브랜드, 목적, 사용자 흐름에 맞게 독립적으로 설계한다.
- 서비스별로 같은 헤더·푸터 로직을 복제하지 않는다. 공통 Shell이 사용자 UI 자산을 배포하고 각 서비스는 표준 데이터 속성과 surface 계약으로 의도를 선언한다.
- 공통 푸터는 본문 흐름 안에 두며, 개인정보처리방침·이용약관·문의·운영주체·저작권 등 사용자에게 필요한 공통 정보를 읽을 수 있는 크기로 제공한다.
- 서비스가 별도의 운영주체 또는 별도 정책을 갖는 경우 해당 서비스 정책이 공통 푸터보다 우선한다.
- 관리자 화면(`admin`)에는 이 사용자 헤더·푸터 원칙을 강제하지 않는다.

> 한 문장 원칙: **헤더와 푸터는 하나의 EKODI 언어를 공유하고, 본문은 각 서비스의 고유한 목소리를 유지한다.**

## 1A. AI·행동 우선 원칙

- 사용자 첫 화면과 공통 Shell은 서비스 전체 목록을 기본 노출하지 않는다.
- 현재 맥락과 사용자의 자연어 의도를 바탕으로 최대 3개의 다음 행동만 먼저 제안한다.
- 전체 서비스 목록은 사용자가 **“모든 서비스 보기”**를 명시적으로 열었을 때만 2차 탐색으로 제공한다.
- 가능한 판단은 EKODI Core의 결정적 규칙으로 먼저 처리하고, 모델 호출이 없어도 탐색과 이동이 동작해야 한다.
- 관리자 화면은 전체 관제가 목적이므로 이 축약 원칙의 예외이며, 사용자 화면과 관리자 화면의 정보 밀도를 구분한다.

> 한 문장 원칙: **사이트를 찾게 하지 말고, 하려는 일을 말하면 다음 길을 보여준다.**

## 2. 구현 계약

공통 모듈:

- 동작: `shell/user-ui-header.js`, 공통 Shell injector
- 필수 사용자 chrome 스타일: `shell/user-ui-shell.css`

기본 동작:

1. Shell surface가 `public` 또는 `workspace`인지 확인한다.
2. 페이지의 기존 사용자 헤더를 탐색하고, 없으면 EKODI 정체성·현재 서비스·My EKODI를 담은 최소 fallback 헤더를 제공한다.
3. 헤더를 화면 상단에 고정하고 실제 높이만큼 spacer를 만들어 본문이 가려지지 않게 한다.
4. 헤더 안에서 제목 후보를 찾아 중앙축에 배치한다.
5. 공통 푸터를 문서 하단의 정상 흐름에 하나만 제공하고 중복 레거시 법적 푸터를 숨긴다.
6. 화면 크기, 방향, DOM 변경, Shell surface 변경 시 자동 재조정한다.
7. 본문 정렬이나 서비스 고유 레이아웃에는 스타일을 주입하지 않는다.

### 2A. 보안·CSP 계약

- 공통 헤더·푸터의 **필수 스타일은 외부 자산 `shell/user-ui-shell.css`로 제공**한다.
- 서비스가 `style-src 'self'`처럼 엄격한 CSP를 사용하더라도 공통 Shell origin(`https://shell.ekodi.kr`)만 허용하면 사용자 chrome이 정상 동작해야 한다.
- 공통 사용자 UI 때문에 기존의 엄격한 서비스 CSP에 `'unsafe-inline'`을 추가하도록 요구하지 않는다.
- 이미 CSP가 없는 레거시 서비스에 Shell이 기본 CSP를 생성할 때는 기존 인라인 스타일 호환성을 깨뜨리지 않도록 단계적으로 이전한다.
- 보안 강화와 UI 일관성 중 하나를 희생하는 방식으로 해결하지 않는다. 공통 UI는 엄격한 CSP에서도 동작하는 구조를 기본값으로 삼는다.

## 3. 권장 마크업

명시적 마크업을 우선한다. 레거시 페이지는 공통 선택자 탐색으로 점진적으로 호환한다.

```html
<header data-ekodi-user-header-root>
  <div data-ekodi-header-side="left">...</div>
  <h1 data-ekodi-header-title>에코디비즈</h1>
  <div data-ekodi-header-side="right">...</div>
</header>
```

- `data-ekodi-user-header-root`: 공통 고정 헤더로 사용할 요소
- `data-ekodi-header-title` 또는 `data-ekodi-header-center`: 화면 중앙축에 둘 제목/핵심 텍스트
- `data-ekodi-header-side="left|right"`: 좌우 제어 영역임을 명시
- `data-ekodi-header-ignore`: 공통 모듈 탐색에서 제외

## 4. 예외

몰입형, 인증형, 결제 집중형 화면처럼 헤더 고정이 사용자 흐름을 방해하는 화면은 예외를 선언할 수 있다.

```html
<html data-ekodi-user-header="immersive">
```

지원 예외 값:

- `off`: 공통 사용자 헤더 모듈 비활성화
- `hidden`: 헤더가 없어야 하는 화면
- `immersive`: 영상, 프레젠테이션 등 몰입형 화면

특정 헤더만 제외하려면 `data-ekodi-header-fixed="off"`를 사용한다.

## 5. 반응형 원칙

- 데스크톱과 모바일 모두 고정 헤더를 기본값으로 한다.
- 제목은 좌우 제어 영역과 독립적인 중앙축을 우선한다.
- 좁은 화면에서는 제목의 최대 너비를 줄이고 말줄임을 허용한다.
- `env(safe-area-inset-top)`을 반영해 노치/모바일 브라우저 안전영역을 보호한다.
- 헤더 실제 높이를 CSS 변수 `--ekodi-user-header-height`로 제공해 앵커 이동과 후속 UI 모듈이 재사용할 수 있게 한다.
- 푸터는 모바일에서 링크·운영정보를 자연스럽게 줄바꿈하고, 작은 글씨로 축소해 정보를 감추지 않는다.

## 6. 접근성과 독립성

- 서비스 원본 헤더의 의미 구조와 버튼/링크 동작을 바꾸지 않는다.
- 키보드 사용자를 위해 링크와 제어 요소에 식별 가능한 focus 상태를 유지한다.
- 공통 모듈은 위치·중앙축·공통 운영/법적 정보만 책임지고 서비스 도메인 로직을 소유하지 않는다.
- 특정 프레임워크, 클라우드, 디자인 시스템에 종속되지 않는 순수 브라우저 계약으로 유지한다.
- 향후 헤더·푸터 구현체를 교체하더라도 서비스는 데이터 속성과 surface 계약만 유지하면 된다.

## 7. 변경 원칙

헤더·푸터 공통 규칙 변경은 공유 Shell에서 한 번만 수행한다. 서비스별 페이지에서 동일 기능을 별도 구현하지 않는다. 서비스 고유 디자인은 헤더 아래와 푸터 위에서 자유롭게 진화할 수 있으며, 공통 모듈은 그 영역을 침범하지 않는다.
